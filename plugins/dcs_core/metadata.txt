It keeps one project per job in Processing/<Name>/ beside the captures, records what each stage published and what it was built from, flags results that are out of date when an earlier stage is re-run, and gives every plugin the same menu, look, chain bar and readers for the mapper's .clraw captures, SBET trajectories and LAS. It has no window of its own.

changelog=1.12.0 (API 13) registry.focus: a plugin can open another one with a given item shown (CloudPro's line separation opens PosPro on a problem area and AlignPro on a line pair). Additive; plugins built for API 12 work unchanged.
    1.11.0 (API 12) New header in every plugin: the chain (PosPro › AlignPro › CloudPro) and the plugin's own steps as two rows of breadcrumbs coloured by state, with the guidance in their tooltips instead of a sentence under the header; the project box holds the plugin's menu; the plugin's tools sit right of it. Plugin windows are always normal windows (no docking, no inner title strip, no Window button). "Finalize" replaces "Publish" in what users read.
    1.10.0 (API 11) Plugins can be told when a stage publishes (registry.on_publish): CloudPro uses it to georeference a job in the background as soon as PosPro and AlignPro are current again.
    1.9.1 Readable lists and tables on Windows: with QGIS 4 the Windows 11 style painted the rows of lists, tables and trees white with light text (RemixPro's recordings table was unreadable except the selected row). Their background and rows are now painted in the dark theme by DCS Core, with each row's own text colours kept, a teal selection band and themed tick boxes. All plugins benefit; no API change (API 10).
    1.9.0 NAD83(CSRS) epochs (API 10): coordinates are moved between reference epochs (for example the observation date and New Brunswick's 1997.0) with NRCan's NAD83v70VG velocity grid, bundled (Open Government Licence - Canada).
    1.8.0 Reliability (API 9): the project file can no longer lose a change when two plugins or two QGIS windows save at once (exclusive locks, a short wait instead of an error, safe takeover of a lock left by a crash, retries on Windows while another program holds a file open). AlignPro and CloudPro results go out of date when a survey line they read changes or a new one is added, also when PosPro processed navigation recordings. System profiles: PosPro and AlignPro saving at the same time keep each other's sections, profiles whose names differ only in case keep separate files, and the recording system's unit serial number is now found. Damaged or partly copied .clraw files no longer stop the line list. Lower memory use reading long SBET trajectories. Navigation packets with a bad checksum are left out. LAS files: correct header flags and date; a failed export leaves no partial file. Floating windows: native title-bar clicks no longer reach the docking code (QGIS 4 / Windows).
    1.7.0 System profiles (API 8): a mapper system's checked antenna offsets, rear axle, IMU, vehicle, Lidar lever arm, mounting angles and latency saved on this computer, matched to a job by the mapper unit and Certus serial numbers, with a shared System profiles window for PosPro and AlignPro.
    1.6.1 Description names the menu correctly: Plugins > Canadian Lidar > Data Systems. No change for the plugins (still API 7).
    1.6.0 Guided steps for every plugin (API 7): a Back / Next bar under the step pages that says whether the step is done and what to press, with Continue in <next plugin> on the last step; the plugin's version is shown after its name in the header (read from the plugin's metadata, so RemixPro shows it too). Plugins that use the Back / Next bar need DCS Core 1.6.0 (PosPro 1.6.0, AlignPro 1.5.0, CloudPro 1.6.0).
    1.5.1 Fix: QGIS 4 on Windows could close with an access violation when you clicked or dragged in a DCS plugin window (PosPro, its quality plots, AlignPro, CloudPro, RemixPro) while it was a floating window. The window's title bar now moves the window itself, and clicks never reach the docking code meant for docked panels. Docked panels behave as before. No change for the plugins (API 6).
    1.5.0 Reads the raw Certus stream for RemixPro (API 6): .anpp files and the /ins/anpp packets of a .clraw, with the raw IMU, raw satellite observations, ephemerides and device information decoded exactly as the mapper decoded them. Marine sonar recordings: reads SonarView .svlog / .svlz (Cerulean Ping packets) and .clraw of kind sonar made by RemixPro; PosPro, AlignPro and CloudPro leave sonar recordings out of their line lists. Nothing else changes for PosPro, AlignPro and CloudPro.
    1.4.0 Mapper 2.10 captures (API 5): lines are grouped from each file's metadata (capture, line), so the new <Project>_L001_..._0001.clraw names, files split over several parts and older captures grouped into lines/ all read correctly, in recording order; navigation recordings (nav/, kind navigation) are never taken as survey lines; DcsProject.survey_clraw_files finds a job's survey lines (the captures' folders, else the job folder) also when the captures are navigation recordings; choosing a folder inside a mapper project (lines/, nav/, a line) makes the mapper project's folder the job folder, named after it.
    1.3.0 The shared header bar for every DCS plugin (API 4): logo, menu group and plugin name, workflow boxes beside them (on a second row when the window is narrow), project box, Window and user guide buttons in the same order everywhere. Window title bars show the plugin name as written. Disabled input fields look disabled (dimmed text on the panel colour).
    1.2.0 The standard plugin window for every DCS plugin (API 3): floating by default, docked only when the user chooses, remembered per plugin, Reset window; safe unloading on QGIS 4. Neutral graphite theme (window #26292D, panels #2E3237, views #2A2D31) so points and coloured classes stand out; status and solution colours unchanged.
    1.1.0 Shared readers for every plugin (API 2): .clraw recordings, Lidar and INS packet decoding, SBET/SMRMSG and LAS, with the Zstandard decoder bundled, so AlignPro and CloudPro use one copy. SBET reading handles a GPS week rollover inside the file. A missing Zstandard decoder is reported instead of every chunk counting as damaged. Plugins can read the menu titles (menu.TOP, menu.GROUP) and use widgets.align_flags.
    1.0.1 "Lidar" spelling throughout.
    1.0.0 First release: shared project (.dcsproj), handover files, staleness, locks, relocation, menu, theme (from PosPro 1.1.4), chain bar.
