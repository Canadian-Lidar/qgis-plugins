{N}Projects and the job folder

PosPro, AlignPro and CloudPro work on one shared processing project per job. The mapper's capture folders are never changed: everything the plugins make goes in a Processing folder.

PathHolds
Job_Oct20/The job folder: the capture folders recorded by the mapper (read only)
Job_Oct20/Processing/<Name>/<Name>.dcsprojThe shared project: captures, shared settings (coordinate system, base station, antennas, Lidar mounting, vehicle) and the state of each stage. A .bak copy is kept beside it.
01_PosPro/, 02_AlignPro/, 03_CloudPro/Each stage's own settings file, work/, log/, and out/ with what it publishes
<Name>.qgzThe QGIS project, when you save it from the project menu

Mapper 2.10 projects

From mapper 2.10 the mapper keeps its own projects. Use the mapper project's folder as the job folder:

PathHolds
Deck_Test/project.jsonThe mapper project: name, id, next line, operator, vehicle
Deck_Test/lines/Deck_Test_L001_20261104_124512/One survey line (one Start/Stop), its files named Deck_Test_L001_20261104_124512_0001.clraw, _0002 … Captures made before 2.10 that the mapper grouped into the project keep their old names here.
Deck_Test/nav/Deck_Test_NAV_20261104_120000_0001.clrawA navigation recording: everything the Certus sent while the project was open (no Lidar). A new one starts at each power-on, project opening, UTC date change and every 2 GB.

If you pick the project's lines or nav folder, or a line folder, the New project dialog takes the mapper project's folder as the job folder and its name as the project name. The survey lines are recognised from what the files record (their line number and capture), not from their names, so a line split over several files is one line and old and new captures mix freely, in recording order. Navigation recordings are never taken as survey lines.

The Processing folder can also live on another drive (choose Elsewhere… when you create the project). Paths are stored relative to the job folder where possible, so a job can be copied or moved as a whole.

The project menu

{PROJECT_MENU_TABLE}

Creating a project

  1. Choose New project… in the project box.
  2. Job folder: the folder that holds the mapper's capture folders. The project name defaults to the folder's name.
  3. Processing folder: inside the job folder by default; Elsewhere… to put it on another drive.
  4. Press OK. The project is created and opened. {AFTER_CREATE}

A project made in any of the three plugins is the same project: open the .dcsproj in another plugin, or click its box in the header.

When the raw data has moved

If the captures are not where they were (another drive letter, a copied job), {NAME} says so when the project opens and asks for the job folder's new location; Raw data moved? Relocate the job folder… in the project menu does the same at any time. The captures are found again by their place in the job folder; nothing goes out of date because of the move.

Out-of-date results

Each stage records what it was built from. When an earlier stage publishes again, the raw data changes, or a shared setting it depends on is edited, the stage turns ⚠ stale in the workflow boxes, with the reason on hover. Run that stage again to bring it up to date. A run that fails or is cancelled keeps the earlier results.
