version=2.0.4
author=Canadian Lidar
email=seantobrien@gmail.com
about=PosPro processes Advanced Navigation Certus logs (.anpp) and mapper captures (.clraw) directly. It extracts the raw IMU and raw GNSS observations, downloads ephemeris, precise products and base-station data, computes base positions by PPP or CSRS-PPP, and runs a tightly or loosely coupled GNSS/INS filter forward and backward with a combined (smoothed) result. Quality is shown on the map and in plots, and the trajectory is exported as SBET/SMRMSG or text. A calibration step solves the antenna lever arms from the drive. Styled like the Mobile Mapper dashboard. Processing runs in a separate engine process (RTKLIB-EX inside), so a fault never closes QGIS.

The Data page and the processing log now warn when the recording lost IMU data (holes in the Certus stream).
    2.0.3 Jobs processed before 2.0.1 with an output point (for example the Lidar from Use offsets from the capture) are flagged when opened: Processing reads "process again" and a message explains that their published trajectory makes AlignPro and CloudPro apply the Lidar offset twice. New projects are named after the first capture date (2026-11-03_1, _2 ...).
    2.0.2 System profiles: System profile... on the Installation page saves the checked antenna offsets, rear axle, IMU and vehicle as the profile of the mapper system that recorded the job (kept on this computer, matched by the unit and Certus serial numbers); when the rover files of a later job from that system are read and its values differ, PosPro offers the profile. AlignPro keeps the Lidar mounting in the same profile. Needs DCS Core 1.7.0.
    2.0.1 Audit fixes. Important if AlignPro or CloudPro use a PosPro trajectory and an output point (Use offsets from the capture) was set: the published trajectory was at that point but labelled as the IMU centre, so the lidar offset was applied twice; it is now always at the IMU centre - process or Export again. The frame is worked out for each run (PPP: ITRF2020; PPK: the base position's frame) and never stored back; tight coupling only starts from GNSS-only solutions made with the same base, position and settings; an unfinished read of the rover files is never reused; review edits made while another job runs are applied when it ends; unloading PosPro stops the running job and releases its DCS lock. Engine 2.0.1: damaged .clraw records are reported and skipped instead of ending the read, dual-antenna jobs sort their epochs in n log n (was quadratic), guards against non-finite filter updates, memory checks. Faster: plots no longer repaint on every mouse move, real-time tracks read with numpy, downloads streamed to disk with a stall timeout and one retry, same-day files refreshed, missing precise products remembered for 6 h, navigation files worked out once per job. Panel: actions off while a job runs and until they can work, Export choices kept, Processing marked out of date when its inputs change, Review done when nothing is over the limits, real-time mode honours the time range, Bridge with IMU and Add plot range named as in the editor.

Installation now comes before Base (the antennas are checked before anything is processed) and Calibration before Review (solving the lever arms means processing again, which would drop hand edits).
